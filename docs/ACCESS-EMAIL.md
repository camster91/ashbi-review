# Sharing, sign-in and email — issue #6

Each review has a random share token, optional expiry and off switch; all guest reads/writes and proxy requests revalidate it. The guest's random device token is hashed in D1 and held in a secure HttpOnly cookie scoped to that review's API path. Guest names are remembered across reloads. Guest identities never grant operator access or resolve/delete powers, and server-side identity supplies comment authors. Public comment responses omit email addresses.

Cameron and Bianca have separate seeded accounts. Magic links contain 256 random bits, are stored hashed, expire after 15 minutes and are consumed atomically with session creation. The token lives in an email URL fragment (not the HTTP URL) and is removed from browser history immediately. The landing page requires an explicit Open workspace click. Sessions use secure HttpOnly SameSite=Lax cookies, expire after 30 days and are revoked on sign-out. Cookie-authenticated writes reject unrelated/null Origins; there is no public signup. Requests for unknown addresses return the same generic message; approved accounts are throttled to one link per minute.

Guest comments and replies enqueue notifications atomically with the comment. The 15-minute Cron freezes at most 100 pending comments into a durable email batch, claims a two-minute delivery lease, and sends one message to both operators. New comments after freezing wait for the next interval; quiet intervals send nothing. Resend idempotency keys use the stable batch ID and identical frozen payload on retries. Failed sends keep the queue; successful sends record the provider ID and clear their queue entries. Resend retains idempotency keys for 24 hours, so a send accepted by the provider followed by a prolonged database outage still needs delivery reconciliation before manual retries after that window.

Configuration: Worker secrets RESEND_API_KEY and EMAIL_FROM; canonical APP_ORIGIN is in Wrangler config. Resend is chosen because no Cloudflare Email Sending sender was configured at the foundation check. No live email, credential change or production migration has been performed here. Migration 0005 adds access/outbox tables and the two approved users.

Tests cover single-use/expired login links, Bianca's distinct identity, logout, cross-origin rejection, guest identity/replies/access restrictions, link expiry/revocation, digest grouping/concurrency/quiet intervals/provider retry/configuration. Chromium adds a fresh phone guest context with no operator test key, persistent named comment, dashboard reply/resolve, guest reload and revoked-link failure. Live magic-link delivery and a real 15-minute Cron digest remain blocked on the Resend sender/key and an approved deployment.
